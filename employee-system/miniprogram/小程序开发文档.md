## 1. 项目概述

本项目是员工管理系统的微信小程序端，基于 uni-app、Vue 3、TypeScript 开发，运行目标为微信小程序。

项目目录：

```text
D:/xiangmu/cainiao/employee-system/
├── backend/       后端 Spring Boot 服务
├── frontend/      Web 前端
└── miniprogram/   微信小程序端
```

小程序目录必须打开：

```text
D:/xiangmu/cainiao/employee-system/miniprogram
```

不要只单独打开 `README.md` 或某个 `.vue` 文件，否则 HBuilderX 会认为这是非项目文件，无法运行到小程序模拟器。

## 8. 请求地址说明

请求封装文件：

```text
miniprogram/utils/request.ts
```

当前请求地址策略：

```ts
const DEVTOOLS_BASE_URL = 'http://127.0.0.1:8080'
const DEVICE_BASE_URL = 'http://192.168.31.139:8080'
```

规则：

| 运行环境 | 请求地址 |
| --- | --- |
| 微信开发者工具模拟器 | `http://127.0.0.1:8080` |
| 真机调试 | `http://192.168.31.139:8080` |

原因：

1. 开发者工具模拟器运行在电脑上，可以访问电脑本机的 `127.0.0.1`。
2. 真机运行在手机上，手机里的 `127.0.0.1` 指手机自己，不能访问电脑后端。
3. 真机必须通过电脑的局域网 IP 访问后端，例如 `192.168.31.139`。

如果电脑 IP 变化，需要修改：

```text
miniprogram/utils/request.ts
```

把 `DEVICE_BASE_URL` 改成新的电脑局域网 IP。

查看电脑 IP：

```powershell
ipconfig
```

一般看无线网卡 IPv4 地址。

## 11. 登录和 Token

登录接口：

```text
POST /auth/login
```

请求体：

```json
{
  "username": "admin",
  "password": "admin123"
}
```

登录成功后返回 JWT Token，小程序会保存：

```text
token
userInfo
```

请求封装会自动加请求头：

```text
Authorization: Bearer <token>
```

如果接口返回 401，小程序会清理登录信息并跳转登录页。

## 12. 常见问题

### 12.1 HBuilderX 提示 Markdown 文件不能运行

原因：当前选中的是 `README.md` 或单独打开的文件，不是项目。

处理：

1. 点击左侧项目根目录 `miniprogram`
2. 或打开 `App.vue`
3. 再点击运行到微信小程序

### 12.2 HBuilderX 启动微信开发者工具失败

报错类似：

```text
IDE service port disabled
```

处理：

```text
微信开发者工具 -> 设置 -> 安全设置 -> 服务端口 -> 开启
```

然后关闭微信开发者工具，重新从 HBuilderX 运行。

### 12.3 微信开发者工具打开后是空白或停在项目列表

处理：

1. 关闭所有微信开发者工具窗口
2. 从 HBuilderX 重新运行
3. 如果仍停在项目列表，手动双击 `mp-weixin`

### 12.4 `request:fail net::ERR_CONNECTION_REFUSED`

常见原因：

1. 后端没有启动
2. 端口不是 8080
3. 真机请求了 `127.0.0.1`
4. 手机和电脑不在同一个 Wi-Fi
5. Windows 防火墙拦截了 8080

检查后端：

```powershell
netstat -ano | Select-String ':8080'
```

本机测试：

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/auth/login -ContentType 'application/json' -Body '{"username":"admin","password":"admin123"}'
```

局域网测试：

```powershell
Invoke-RestMethod -Method Post -Uri http://192.168.31.139:8080/auth/login -ContentType 'application/json' -Body '{"username":"admin","password":"admin123"}'
```

### 12.5 `request:fail url not in domain list`

原因：微信开发者工具开启了合法域名校验，本地 IP 或 HTTP 地址被拦截。

处理：

```text
微信开发者工具 -> 详情 -> 本地设置 -> 勾选“不校验合法域名、web-view、TLS版本以及HTTPS证书”
```

同时确认：

```text
project.config.json -> setting.urlCheck = false
project.private.config.json -> setting.urlCheck = false
```

### 12.6 本地模拟器请求 `192.168.31.139` 出现 502

原因：微信开发者工具本地调试代理转发局域网 IP 时可能返回 `502 Bad Gateway`。

处理：本地模拟器使用 `127.0.0.1`，真机使用局域网 IP。当前项目已在 `utils/request.ts` 中自动判断。

### 12.7 修改代码后真机没有更新

处理：

1. HBuilderX 停止运行
2. 关闭微信开发者工具项目窗口
3. 重新运行到微信开发者工具
4. 查看控制台 `[Request] URL:` 是否是最新地址

## 13. 开发规范

### 页面开发

1. 页面放在 `pages/` 下。
2. 新页面必须注册到 `pages.json`。
3. 页面跳转使用 `uni.navigateTo`、`uni.switchTab`、`uni.reLaunch`。
4. Tab 页面只能使用 `uni.switchTab` 跳转。

### 接口开发

1. 接口统一写在 `api/` 目录。
2. 不要在页面里直接写 `uni.request`。
3. 请求统一走 `utils/request.ts`。
4. 需要登录的接口由请求封装自动带 Token。

### 状态管理

登录状态放在：

```text
store/auth.ts
```

页面需要用户信息时优先从 auth store 获取。

### 样式开发

公共样式放在：

```text
app.scss
styles/
uni.scss
```

页面样式写在当前 `.vue` 文件的 `<style lang="scss">` 中。

## 15. 小程序上线发版流程

### 15.1 准备线上后端

正式小程序不能使用本地地址：

```text
http://127.0.0.1:8080
http://localhost:8080
http://192.168.x.x:8080
```

必须准备线上 HTTPS 接口域名，例如：

```text
https://api.example.com
```

上线前需要完成：

1. 后端部署到服务器。
2. 后端服务可以公网访问。
3. 域名已备案。
4. 域名已配置 HTTPS 证书。
5. 登录接口、业务接口在线上环境测试通过。

后端线上测试示例：

```powershell
Invoke-RestMethod -Method Post -Uri https://api.example.com/auth/login -ContentType 'application/json' -Body '{"username":"admin","password":"admin123"}'
```

### 15.2 生产数据处理

项目开发阶段有很多演示数据，例如员工、部门、考勤、公告、请假、日报、报销、合同、工资条等。这些数据只适合本地演示，正式上线不要导入。

上线数据原则：

1. 保留管理员账号。
2. 不保留演示员工账号。
3. 不保留演示业务数据。
4. 生产库使用空业务表。
5. 上线后由管理员在后台录入真实员工、部门、公告等数据。

后端已提供两个生产相关 SQL：

| 文件 | 用途 |
| --- | --- |
| `backend/src/main/resources/db/production-init.sql` | 全新线上库初始化，只建表并创建 admin 管理员 |
| `backend/src/main/resources/db/production-clean-demo-data.sql` | 已经导入演示数据的库，清理业务数据并保留 admin |

不建议线上直接执行这些演示 SQL：

```text
backend/src/main/resources/db/data.sql
backend/src/main/resources/db/init.sql
backend/src/main/resources/db/add_employee_users.sql
backend/src/main/resources/db/insert_contract_data.sql
backend/src/main/resources/db/create_reimbursement.sql
```

这些文件包含演示员工、演示账号、考勤、日报、报销、合同、工资条等数据，适合本地开发或演示，不适合正式环境。

#### 全新生产库

如果线上数据库是全新的，执行：

```sql
source backend/src/main/resources/db/production-init.sql;
```

或者在 MySQL 客户端中直接导入：

```powershell
mysql -u root -p < D:/xiangmu/cainiao/employee-system/backend/src/main/resources/db/production-init.sql
```

执行后只有一个管理员账号：

```text
账号：admin
默认密码：admin123
```

首次登录后必须立即修改管理员密码。

#### 已有演示数据的库

如果线上库已经误导入了演示数据，先备份数据库，再执行清理脚本：

```powershell
mysqldump -u root -p employee_db > employee_db_backup.sql
mysql -u root -p employee_db < D:/xiangmu/cainiao/employee-system/backend/src/main/resources/db/production-clean-demo-data.sql
```

清理脚本会删除：

1. 员工数据
2. 部门数据
3. 考勤数据
4. 公告数据
5. 请假数据
6. 日报数据
7. 报销数据
8. 合同数据
9. 工资条数据
10. 除 admin 外的演示用户

清理脚本会保留：

```text
admin 管理员账号
```

注意：清理脚本会删除业务数据，必须先备份。

### 15.3 管理员账号安全

管理员账号不能去掉，否则系统上线后无法进入后台管理。

后端已经做了保护：

1. 启动时如果不存在 `admin`，会自动创建管理员。
2. 启动时如果 `admin` 已存在，不会再重置密码。
3. 如果 `admin` 账号角色被误改，会恢复为 `admin`。
4. 后台账号管理中不能删除管理员账号。
5. 后台账号管理中不能把管理员降权。
6. 后台账号管理中不能修改管理员用户名。

生产环境建议通过环境变量设置初始管理员密码：

```powershell
$env:APP_ADMIN_USERNAME="admin"
$env:APP_ADMIN_PASSWORD="请改成强密码"
$env:APP_ADMIN_REAL_NAME="系统管理员"
```

Linux 示例：

```bash
export APP_ADMIN_USERNAME=admin
export APP_ADMIN_PASSWORD='请改成强密码'
export APP_ADMIN_REAL_NAME='系统管理员'
```

对应后端配置：

```yaml
app:
  admin:
    username: ${APP_ADMIN_USERNAME:admin}
    password: ${APP_ADMIN_PASSWORD:admin123}
    real-name: ${APP_ADMIN_REAL_NAME:系统管理员}
```

上线后不要长期使用默认密码 `admin123`。

### 15.5 修改生产环境接口地址

上线前需要把生产环境接口地址改成线上 HTTPS 域名。

当前请求封装文件：

```text
miniprogram/utils/request.ts
```

当前本地开发策略：

```ts
const DEVTOOLS_BASE_URL = 'http://127.0.0.1:8080'
const DEVICE_BASE_URL = 'http://192.168.31.139:8080'
```

上线前建议改成区分开发环境和生产环境：

```ts
const DEVTOOLS_BASE_URL = 'http://127.0.0.1:8080'
const DEVICE_BASE_URL = 'http://192.168.31.139:8080'
const PROD_BASE_URL = 'https://api.example.com'

const getBaseUrl = () => {
  if (import.meta.env.PROD) {
    return PROD_BASE_URL
  }

  const systemInfo = uni.getSystemInfoSync()
  return systemInfo.platform === 'devtools' ? DEVTOOLS_BASE_URL : DEVICE_BASE_URL
}
```

这样：

| 场景 | 请求地址 |
| --- | --- |
| 本地模拟器 | `http://127.0.0.1:8080` |
| 本地真机调试 | `http://192.168.31.139:8080` |
| 正式发布包 | `https://api.example.com` |

### 15.12 常见上线问题

#### 请求失败：url not in domain list

原因：线上接口域名没有配置到微信公众平台合法域名。

处理：

```text
微信公众平台 -> 开发 -> 开发管理 -> 开发设置 -> 服务器域名
```

添加线上 HTTPS 域名。

#### 请求失败：不支持 HTTP

原因：正式版小程序不能请求普通 HTTP 接口。

处理：后端配置 HTTPS 证书，并改用 `https://` 域名。

#### 审核员无法登录

常见原因：

1. 没提供测试账号。
2. 测试账号密码错误。
3. 后端线上数据库没有初始化用户。
4. 线上接口被防火墙拦截。
5. Token 或登录接口异常。

处理：提交审核时填写可用测试账号，并在提交前用体验版登录验证。

#### 体验版正常，正式版异常

重点检查：

1. 体验版是否勾选了“不校验合法域名”。
2. 正式版请求域名是否在公众平台配置。
3. 发行包是否仍然请求本地地址。
4. 后端是否限制了来源、IP 或请求头。

- 实现Pinia认证状态管理

### 核心代码：API拦截器

```javascript
// src/api/auth.js - 请求拦截器
api.interceptors.request.use(config => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`  // 每次请求带Token
  }
  return config
})

// 响应拦截器 - 统一错误处理
api.interceptors.response.use(
  response => response,
  error => {
    if (error.response?.status === 401) {
      authStore.logout()           // 清除登录状态
      message.error('登录已过期')   // 提示用户
      router.push('/login')        // 跳转登录页
    }
    return Promise.reject(error)
  }
)
```

### 核心代码：Auth Store

```javascript
// src/store/auth.js - 认证状态管理
export const useAuthStore = defineStore('auth', {
  state: () => ({
    token: '',        // 登录凭证
    username: '',     // 用户名
    role: '',         // 角色: admin / employee
    realName: ''      // 真实姓名
  }),

  getters: {
    isLoggedIn: (state) => !!state.token,       // 是否已登录
    isAdmin: (state) => state.role === 'admin'   // 是否管理员
  },

  actions: {
    async login({ username, password }) {
      const res = await api.post('/auth/login', { username, password })
      this.token = res.data.data.token
      this.role = res.data.data.role
      localStorage.setItem('token', this.token)  // 持久化存储
    },
    
    logout() {
      this.token = ''
      localStorage.clear()
    }
  }
})
```

### 登录流程图（给领导看的）

```
用户输入账号密码
       ↓
前端 POST /api/auth/login {username, password}
       ↓
后端验证 → 返回 { token, role, userId }
       ↓
前端存储Token到localStorage
       ↓
后续每次请求自动携带 Authorization: Bearer xxx
       ↓
后端验证Token → 返回数据 或 401(过期)
```

```javascript
// src/router/index.js
const routes = [
  {
    path: '/',
    component: Layout,
    meta: { requiresAuth: true },  // 需要登录
    children: [
      {
        path: '/employees',
        component: () => import('../views/employees/EmployeeList.vue'),
        meta: { roles: ['admin'] }  // 仅管理员可见
      },
      {
        path: '/users',
        component: () => import('../views/users/UserList.vue'),
        meta: { roles: ['admin'] }  // 仅管理员可见
      },
      // ...其他路由
    ]
  }
]

// 全局前置守卫
router.beforeEach((to, from, next) => {
  const authStore = useAuthStore()

  // 1. 未登录 → 跳转登录页
  if (!authStore.isLoggedIn && to.meta.requiresAuth !== false) {
    return next('/login')
  }

  // 2. 角色不匹配 → 回首页
  if (to.meta.roles && !to.meta.roles.includes(authStore.role)) {
    return next('/dashboard')
  }

  next()
})
```

  timeout: 10000

  api.get('/employees', { params })
  // 调用: GET /api/employees?page=1&pageSize=10&keyword=张三

  api.post('/employees', data)

  api.put(`/employees/${id}`, data)

export const deleteEmployee = (id) =>
  api.delete(`/employees/${id}`)

## ❓ 领导可能问的问题 & 回答话术

### Q1：后端是怎么实现的？
> **话术：** "后端是同事用Spring Boot + MyBatis Plus开发的RESTful API，我主要负责前端对接。后端提供了标准的JSON格式接口，我用Axios封装了请求层，通过拦截器统一处理认证和错误。具体的技术细节可以问后端同事。"

### Q2：权限控制是怎么做的？
> **话术：** "我用了三层权限控制：
> 1. **路由层面**：用Vue Router的`beforeEach`守卫，根据用户的`role`字段判断是否有权访问
> 2. **菜单层面**：用`v-if="authStore.isAdmin"`控制侧边栏菜单显隐
> 3. **接口层面**：后端也有校验，即使前端绕过也会返回403"

### Q3：Token过期怎么处理的？
> **话术：** "我在Axios响应拦截器里统一处理的。当后端返回401状态码时，自动清除本地存储的Token和用户信息，然后跳转到登录页提示用户重新登录，用户体验比较好。"

### Q4：为什么用Pinia不用Vuex？
> **话术：** "因为项目用的Vue3，Pinia是官方推荐的状态管理库，API更简洁，支持Composition API，TypeScript支持也更好。而且体积更小，性能更优。"

### Q5：你遇到的最大困难是什么？怎么解决的？
> **话术：** "主要是前后端联调时的一些问题，比如：
> 1. **跨域问题**：用Vite的proxy代理解决
> 2. **接口格式不一致**：和后端同事对齐了统一的`{code, message, data}`格式
> 3. **Token传递**：封装了请求拦截器自动携带
> 4. **浏览器缓存**：重启dev server解决"

### Q6：账号管理模块是你独立完成的吗？
> **话术：** "是的，包括用户列表页、新增/编辑表单、密码重置功能都是我开发的。后端提供了6个CRUD接口，我完成了前端的所有交互逻辑、表单验证、状态管理，以及路由和菜单的权限配置。"
